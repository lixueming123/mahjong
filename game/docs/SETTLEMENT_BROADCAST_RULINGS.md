## §2 统一参数表（单一真值源）

### §2.1 时间预算（唯一公式）

> **v1.1 修正（音效实测后）**：原「播报 7000 + 阅读 5000」改为「播报 **9000** + 阅读 **3000**」，**局间总窗口仍 12000 不变**。理由：音效实测「门前清一番」=1327ms、「合计四番」=957ms、「庄家加一番」=1204ms，7000ms 装不下六段完整语音（这六段没有任何一段能容纳自己最短的句子），只能全段截断——比没语音更像 bug。6 段静态铺满期间玩家**本来就在同步阅读**，故播报后的独立阅读窗从 5000 收到 3000 不损失阅读量。

```
interlude_ms = game_end.interlude_ms，缺省 12000
播报窗 budget = clamp(interlude_ms - 1500, 4200, 10500)
TOTAL         = Σ 各段时长（语音驱动）                 ≤ budget   ← 唯一硬约束
阅读时间      = interlude_ms − 实际 TOTAL（**动态，不是常量**）
尾保留        = 400ms（距服务端推进的余量）

# 有语音时逐条停留由句子长度驱动（v1.3）
D_item = max(1200, 该句实测时长 + 150)

# 补 hold = **短局地板 8000**，见 §2.8（v1.6 定稿）：只保底，不拉伸
```

> **v1.3 修正（用户验收反馈 + 对标《明星三缺一 2004》）**：原「播报 9000 + 阅读 3000」改为「播报窗 **10500**」，`budget = clamp(interlude − 1500, …)`，**局间总窗口仍 12000 不变**（用户已确认 12s）。
> 两点理由：① 语音落地后，静默阅读窗的价值大幅下降——**念白本身就是节奏**，玩家边听边看，不需要事后干等；② 9000 只能覆盖 `n≤3` 且每行 900ms，实际听感是「一项一项往前赶」，与《明星三缺一》那种「每项念清楚」的节奏差一档。10500 + `D_item ≥ 1200` 才能让每个番种名读完不被切。
>
> **v1.4 → v1.5（S-3 立而后废，记进历史）**：v1.4 曾按「播报不得早于 `budget×0.85` 结束」加过补足逻辑。
> 实测发现补出来的时间是「盯着播报中的空白」，而且 1 番种的 6.8–7.1 s 本来就是合理节奏 —— **v1.5 全部撤回**。
> 现在唯一的硬约束是 `TOTAL ≤ budget`；`DONE → game_start` 的间隔就是阅读时间，随局型在 1.6–5.2 s 之间浮动。

### §2.2 段结构（六段 + 开场，唯一编号）

| 序 | 段 | 屏上位置（两阶段 A） | 数据源 |
| --- | --- | --- | --- |
| — | **开场**（和牌方式） | 字幕条首句 + 标题行 | `reason` / `win.seat` / `win.from_seat` |
| 1 | 番种明细 | S1 区 8 槽（`yaku[]` 直渲，不排序；`n>8` 第 8 槽合并行） | `win.yaku[]` |
| 2 | 番种合计 | S2 格 `(652,380,206,44)` | `han_breakdown.base` |
| 3 | 加成 + **合计番数** | S3 格 `(874,380,226,44)`，文案 `+N = N 番` | `han_breakdown.dealer` / `total` |
| 4 | 封顶 | S4 格 `(758,440,210,40)`（三子态） | `base + dealer` vs 6 |
| 5 | 倍率 | S5 格 `(982,440,120,40)` | `win.multiplier`（=2^total） |

### §2.3 布局：两阶段（v1.2，三区方案作废）

**阶段 A（播报期，`game_end` 且 `match_end == null`）**

| 区块 | rect | 备注 |
| --- | --- | --- |
| 字幕条 | `(164,104,952,32)` | 左 4px 金竖条；≤24 汉字；播完停最后一句；播报期显示「播报中…」**不显示秒数** |
| 舞台背景层 | `(164,234,952,366)` | 播报期专用底（覆盖四卡/战绩/手牌所在区域） |
| S1 番种区 | `(180,240,920,208)` | **8 槽 × 行高 26 / 字号 18**（原 15px·19px 方案作废） |
| S2/S3 并排 | `(180,380,...)` 两格 | 牌型番合计 / 加成+合计番数 |
| S4/S5 并排 | `(180,440,...)` 两格 | 封顶 / 倍率 |
| S6 四户 | `(180,540,920,48)` | 四户横排含 `±delta` |
| 和牌张 | `(982,240,120,120)` | **必须保留**（番种成立的物证），移右上角 |
| 隐藏 | 四座位卡片 / 战绩块 / 手牌区 | 播报期不画 |

**阶段 B（播报结束 → `game_start`）**：**完全回到 v2.0 §9.2 现状，一字不改**（四卡 `y130 h96`、手牌 `(164,386,952,100)`、战绩块原样）。**禁止**任何既有 rect 变更（原「四卡 h96→88」批准作废）。

**两条实现硬约束**：
1. **文本缓存**：`(text,color,size,alpha)` → `Surface` 的 LRU 缓存，`size + alpha` 为键。8 条番种 × 2 元素 + 其余共 20 段/帧，**不缓存会触发 20 次 `font.render` + `convert_alpha()` 分配**，是 p95 超标的首要风险。
2. **绘制预算**：阶段 A 最坏帧 **≤56 次 draw**（含 S1 8 槽 ×3 + 字幕条 4 + S2–S6 共 9 格 + 和牌张 3 + 分隔线 2 + 高亮条 1）；>56 必须同帧合并，不得靠少画字省调用。

新增颜色 4 个：`BC_ZONE(14,22,20,150)` / `BC_ACTIVE_BG(255,200,64,40)`（α 40，非 30 —— 3.6:1 太低，α40 达 5.5:1）/ `BC_CAPTION_BG(0,0,0,120)` / `BC_CAP_FILL(255,200,64,40)`。字号：S1 用 `FS_H3 22`（原 `FS_SMALL 15` 作废），其余按 UI v1.1 §4.2。

**高亮三态（v1.2）**：未播 = 条宽 **0** / 字 `TEXT_DIM`；当前 = 条宽 **4** / 字 `TEXT` + 底 `BC_ACTIVE_BG`；已播 = 条宽 **2** / 字 `TEXT`（**满色，不许更暗** —— 「已讲完更暗」由条宽承载，不由亮度承载）。三态**无插值**。

### §2.5 交互

| 项 | 裁定 |
| --- | --- |
| 跳过播报 | **采纳**：`SPACE` / `RETURN` / `ESC` / 左键任意位置；起播 100ms 后可跳；180ms 快进一次走完（MOTION §6.4 曲线）；跳过后仍走 220ms 收束 |

| `--no-feel` | 完全不播报，退 v2.0 静态页 + 5s 秒数倒数 |

### §2.6 解析降级（ARCH L0–L3 为准）

`han_breakdown` 缺失 → 用 `yaku[]` 求和 + `dealer_bonus` 兜底（L1）；`yaku` 键缺失 ≠ 0 番（L2 显示「明细不可用」，**只播结论三句** `vo_han_*`/`vo_mult_*`/`vo_pay_*`、不播番种，并记 WARN）；全缺（L3）不播报。**禁止**用 `len(yaku)==0` 判「缺失」，必须判「键是否存在」。

> **v1.5 修正**：L2 原为「不播报」，现改为「只播结论」。理由：L2 的含义是「服务端没发 `yaku` 字段」（协议异常），**异常时让功能整体消失，比降级播报更糟**——玩家会以为"这局没有播报"，而不是"明细缺失"。

### §2.8 短局地板（v1.6 定稿）

```
pad_target = max(natural_total, min(8000, budget - 40))    # 仅和牌局
荒庄豁免（3.9s 合理，无番可讲）
```

- **只保底，不拉伸**：`natural > 8000` 的局一律不动。理由：1 番种局自然长 6764ms，念完 5 句才 6.7 秒，观感"没反应过来就完了"；但把短局补到 10.5s 又变成"用静默掩盖内容少"。地板解决前者，不制造后者。
- **实测区间**：1 番种 8000 / 2 番种 8320 / 3 番种 9558 / 密集 10151–10361 / 荒庄 3907。
- 阅读时间 = `interlude(12000) − 实际播报长`，是**动态量**（1 番种剩 4000ms，密集局剩 1600ms）。`1500` 只是预算扣减额，**不是阅读窗上限**。
- **历史表述全部作废**：U1「不补」、S-3「补到预算」、以及 v1.5 的「补足上限 2000」，三条都不得再引用。
