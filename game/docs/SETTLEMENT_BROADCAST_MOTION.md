## 0. 三个前置结论

### 0.1 时长是**入参**，不是我定的

| 输入 | 来源 | 值 |
| --- | --- | --- |
| `interlude_ms` | `game_end` 顶层字段（ARCH §3.4） | 缺省 **12000** |
| `B`（播报窗） | `clamp(interlude_ms − 3000, 4200, 9000)` | `interlude=12000` ⇒ **9000** |
| 三档门槛（按 `B` 判，不按 `interlude`） | RULINGS §2.1 | `<5100` 不播报；`5100–6200` 播报无语音；`≥6200` 播报+语音 |

**总时长恒等式（本文唯一预算式）**

```
无语音档：TOTAL(n, han) = 2820 + n × D + 96 × han
           D = clamp((B − 2820 − 96·han)/n, 240, 900)，n = min(len(yaku), 7)

有语音档：TOTAL = 120 + Σ_i D_i + 120 + 520 + 460 + 300 + (96·han+200) + 880 + 220
           D_i = max(1000, manifest_i + 100)   # manifest_i = 第 i 句实测时长
           若 TOTAL > B ⇒ 走 Tier 降档（删句，**逐条高亮仍走完 n 条**）
```

两档都收敛到 `2820 + ΣD + 96han`（`2820 = 120 + 120 + 520 + 460 + 300 + 880 + 220 + 200`，其中 `200` 是 `MULT` 的常数项，故 `MULT(han) = 96han + 200`）。
⇒ **「倍率段 = 96×han + 200，其余固定」就是 RULINGS `2820` 常数的展开形式**，两者不是两套数。

### 0.2 时间轴是绝对时间轴，不消费 `dt`，不用 `get_busy()`

进度按 `ui.now`（`time.monotonic()`）与**预先算好的绝对时刻表**比较：`t_k` 一次算完，每帧只做 `now >= t_k` 比较。
- 这是对 `F-G-02`（`dt` 钳 50 ms）的显式例外，判据：播报是「叙述」不是「反馈」，掉帧后必须跳到**正确的步**；
- 同时满足 AUDIO §3.7 硬约束 1（「**不得用 `get_busy()` 轮询推进**」）：`get_busy()` 与文件时长有 10–40 ms 偏差，累积后高亮会飘。

### 0.3 播报不得吃 `F-AN-04` 的 2.0 加速态

全部 `duration` 用 `ms / 1000.0`，**禁止调用 `feel.scaled()`**（`feel.py:183` 会除以 `speed()` ∈ {1.0, 2.0}）。

### 2.1 荒庄（`reason == "draw_exhausted"`，`win == null`）

| 档 | 时长 | 构成 |
| --- | --- | --- |
| **有语音** | **由语音驱动，硬上限 3600** | 三句（`荒庄` / `本局不计分` / `庄家连庄`）+ 四级间隔，实测 ≈2900；看门狗到 3600 强制收尾 |
| **无语音 fallback** | **2700** | `3 × 700 + 2 × 280`（AUDIO §3.7 锚点 B 的 fallback 节拍） |
| 高亮推进 | 3 步 | 番种区「无番种（荒庄）」→ 链区（段5b 显示「不计分」，**不给 ×1**）→ 支付区（全 `ZERO_SCORE`） |

`3600` 是硬上限，超过即 `fadeout(40)` + 高亮 snap 全亮（AUDIO §3.5 看门狗口径）。

### 2.2 `S4` 未触发时（`base + dealer < 6`）

段长**恒 300**（保公式不漂移），但内容分两段：前 **180 ms** 高亮停在该行（字幕不换），后 **120 ms** 静默 hold。
**不压成 0 的理由**：RULINGS 的 `2820` 常数把段4 算成 300 固定；把它压成 0 会让 `TOTAL` 与 `2820` 公式脱钩，进而让 §2 的校验表失效。180+120 是「读得到但不占叙事的行进」。
`base + dealer == 6`（**恰好满额**）时该段**正常占满 300**：这是「打满」不是「被砍」，是真实语义节点（UI §3.4 三子态第 2 行）。

### 2.3 掉帧 / 看门狗

| 场景 | 行为 | 依据 |
| --- | --- | --- |
| 单帧卡顿 300 ms | 按 `ui.now` 跳到正确的步（可能跳过 1–2 步），不追帧 | §0.2 |
| **单步卡死**（某句解码/绘制异常） | **看门狗**：每步最长等待 = 该步预估时长 + **400 ms**，超时强制推进并记 WARN | AUDIO §3.7 硬约束 2 |

| `match_end` 到 | `abort("match_end")` + VO `fadeout(80)` + 清队列，切场终页 | RULINGS C8 / AUDIO §3.8 |

## 三、高亮的推进节奏

### 3.1 三态 = UI §3.7（唯一权威，本文不重定义）

| 态 | 条宽 | 行底 | 文字 |
| --- | --- | --- | --- |
| 未播 | **0 px** | 无 | `T.TEXT_DIM` |
| 当前 | **4 px** `T.SELECT` | `T.BC_ACTIVE_BG (255,200,64,30)`，圆角 2 | 正文 `T.TEXT` 粗体；番值列 `T.SELECT` |
| 已播 | **2 px** `T.PANEL_EDGE` | 无 | `T.TEXT` 常规 |

**同时只有一行「当前」；跨区步进时上一区立即转「已播」；三态之间无插值**（UI §3.7 明令：步进本身就是节奏源，再叠淡入会让字幕与高亮错拍）。

### 3.2 每步停留 `D`（两档，唯一公式）

**无语音档（含 fallback / `M` 静音 / 语音全缺）**

```
D(n, han) = clamp( (B − 2820 − 96·han) / n , 240 , 900 )
            n = min(len(yaku), 7)   # 番种区 7 槽（UI §3.3），第 7 槽合并行
```

**有语音档**

```
D_i = max( 1000 , manifest_i + 100 )      # V12；D_MAX=900 不适用
TOTAL = 2820 + Σ D_i + 96·han ；若 > B ⇒ 走 Tier 降档（删句，逐条高亮仍走完 n 条）
```

| 项 | 值 | 依据 |
| --- | --- | --- |
| `D_MIN`（无语音） | **240** | 4 字中文名最短认读 200 + 40 切换余量 |
| `D_MAX`（无语音） | **900** | RULINGS §2.1 公式内即此值；`B=9000` 下 `n ≤ 6` 全部触顶 |
| `D_i` 下限（有语音） | **1000** | V12：`max(1000, 句长+100)`；4 字名实测 ≈1470 ⇒ 实际 `D_i ≈ 1470–1570` |
| 字幕领先量 | **80 ms** | AUDIO §3.7 硬约束 3：字幕**早于**声音 80 ms（先读后听） |

**读表要点**
1. `n ≤ 6` **全部触 900 上限**（总长 3720–8796，均 < 9000）⇒ 典型局（2–4 项）不会有"压迫感"，播完倒计时**提前出现**（这正是设计意图：播报不占满窗口）。
2. 只有 `n = 7` 才真正吃到预算：`han=6` 时 `D = 800`。
3. `n = 8` 起封 7 槽（第 7 槽「另 {n−6} 项 · {Σ} 番」），数值与 `n = 7` 行**逐格相同**。
4. `D_MIN = 240` 在 `B = 9000` 下**永不触发**（最低 800）；它的作用在 `B = 5100` 门槛档（§3.4）。

### 3.5 高亮在哪一刻切换（本文真正拥有）

| 事件 | 切换时刻 | 精度 |
| --- | --- | --- |
| 步 `k` 开始 | `T_BC + t0(k)`，`t0` 见 §2 | **单帧内**：旧行→已播、新行→当前、字幕换句，同一帧完成 |
| 步 `k` 结束 | 恰为 `t0(k+1)`（严格首尾相接，无间隙、无重叠） | 禁止「先撤高亮再上新高亮」的两帧过渡 |
| 有语音时字幕 | **该步 `t0` 之前 80 ms**（`t0 − 80`） | 字幕条先出字，音频后到（AUDIO 硬约束 3） |
| 收束（S7） | `T_BC + TOTAL − 220` | 全行→已播；竖条 `alpha 0.6→0`、**120 ms linear** 后消失 |
| 跳过 | 按键帧 + **180** | §6.5 |

> S7 的 120 ms 竖条淡出是唯一保留的"过渡"：三态没有「空态」，所以它不是「三态之间」的插值。UI 若判定违反 §3.7，把 `F-BC-30` 设为 **0**（硬消失）即可。

### 3.6 拒绝滑动（三条理由，v1.0 原样保留）

1. 门槛档 `D = 243 ms` 时，滑移至少要 120 ms 才看得出方向，与下次切换重叠 ⇒ 两条竖条同时在动，读者分不清"现在讲哪条"。
2. 跨区纵向距离最大 152 px（番种区 y248 → 支付区 y306），滑移会**穿过**还没讲到的段，等于提前泄底（先看到「倍率」再看到「番种合计」）。
3. 自上而下的阅读惯性本身就给出方向，瞬切代价为零。

**唯一允许的位移**：支付区数值滚动（§4.3）——发生在同一槽位内的数字上，不产生空间歧义。

### 4.1 倍率阶梯（S5）

## 五、与语音的对齐

### 5.1 主时钟：固定时刻表（由 manifest 预计算），语音是时间表的**数据源之一**

```
t_0 = T_BC + 120
t_{i+1} = t_i + D_i          # D_i 有语音 = max(1000, manifest_i + 100)
                             #   无语音 = D（§3.2 无语音公式）
每帧只做 now >= t_k 的比较，不轮询 get_busy()、不等待音频
```

这条与 AUDIO §3.7 锚点 A/B **可调和**：AUDIO 的「锚点 A = 该句 `play()` 的同一帧切换高亮」在**时刻表预计算**后自动成立（因为 `play()` 就发生在 `t_i` 那一帧），而 AUDIO 硬约束 1 要求「绝对时刻表，不用 `get_busy()`」正是本文 §0.2。

| V2 | **语音缺失就静默开始**：该句不发、不排队、不补播；`D_i` 退回无语音 `D` | AUDIO §3.8 |

## 六、暂停倒计时与跳过

### 6.1 倒计时行三态（RULINGS §2.5 为准）

| 态 | 触发 | 行 1（`FS_H3 22`，`(430,604,420,26)`） | 行 2（`FS_SMALL 15`，`(430,632,420,22)`） |
| --- | --- | --- | --- |
| `NORMAL` | 不播报（`B<5100` / `--no-feel` / L3） | 「下一局即将开始（{N} 秒）」 | 「下一局庄家：{昵称}」 |
| `PAUSED` | 播报中 | **「播报中 · 空格跳过」**（**不显示任何数字**） | 同上 |
| `RESUMING` | 播报结束 / 跳过 | 「下一局即将开始（{N} 秒）」，`N` **按 `interlude_ms` 重算** | 同上 |
| 场终 | `match_will_continue == false` | 「本场结束，正在统计排名…」（两态都这句） | 不显示 |

`PAUSED` 附加：该行 1 px `PANEL_EDGE` 描边 `alpha 0.6→1.0` 呼吸，周期 **1200 ms**（复用 `F-CL-01`）；`RESUMING` 时 200 ms linear 淡出到 0。
> 这是本文新增的唯一样式，UI §4.6 未给描边。若 UI 否决，降级为「无描边」，只留文案，不阻塞。

### 6.2 为什么是「不显示数字」而不是「冻结数字」

| 方案 | 问题 |
| --- | --- |
| 冻结在「5 秒」 | 完全静止的数字被读成**卡死**，玩家会去点屏幕救活；且冻结值与真实剩余（`interlude − elapsed`）必然越来越不一致 —— 12 s 窗口下播到 5 s 时真实剩 7 s，冻结的 5 会**跳到 7** |
| 继续递减 | 与「播报中」语义混在一起，玩家会以为下一局马上开始而乱按 |
| **不显示（本文 / RULINGS §2.5）** | 把「等待」换成「内容」；播完按 `interlude_ms` 一次性给出**真实剩余**，不撒谎、不跳动 |

### 6.3 恢复路径（逐帧可核）

```
S7（T_BC + TOTAL − 220）：
  1) 全部行 → 已播；竖条 120 ms linear 淡出（F-BC-30，可设 0）
  2) 字幕条停在最后一句（RULINGS C7：不消失，直到切屏）
  3) 倒计时 → RESUMING（200 ms crossfade）；N = ceil((result_at + interlude/1000 − now))
     实测：interlude=12000、播报到 8.9 s ⇒ N = ceil(12 − 8.9) = 4 秒
  4) 和牌张 / 手牌 / 四卡 / 战绩块全程可见（RULINGS C6：信息只增不删），无揭示动画
  5) 等 game_start（服务端 timer）⇒ app.py 既有 RESULT→TABLE 切屏
```

**不存在「重新数 5 秒」**：`N` 恒由 `interlude_ms` 与当前时刻算 ⇒ 不会出现「数到 0 但下一局没来」（这是旧客户端在 `interlude=12000` 下会「卡在 0 秒 9 秒」的回归，v1.2 结构上不会发生）。

### 6.4 跳过快进（180 ms，RULINGS §2.5 明示「按 MOTION §6.4 曲线」）

| 项 | 参数 |
| --- | --- |
| 触发器 | `SPACE` / `RETURN` / `ESC` / **页面内左键任意位置** |
| 可用时机 | `T_BC + 100 ms` 之后；S7 起点之后不可跳过 |
| 动作 | ① 所有行**同帧**→已播；② 字幕**同帧**跳末句；③ 支付 P1/P2 数值（若未滚完）在 **180 ms** 内 `ease_out_cubic` 收敛终值；④ VO `fadeout(80)` + 清队列 |
| 之后 | **仍走 220 ms 收束**（RULINGS §2.5 明文） |
| 为什么没有「竖条一扫而过」 | v1.0 的 180 ms 扫尾（竖条拉满 + alpha 归零）已删除：它是唯一为「跳过」新增的过渡，与 UI §3.7「三态无插值」直接冲突，且跳过时玩家要的是"立刻结束"。180 ms 只留给**数字收敛**（数字是唯一允许动的对象） |
| 发帧 | **不发任何帧**（局间出站帧数 = 0，`A1_ACCEPTANCE` M8 冻结口径） |
| 幂等 | 播报期重复按键无效（`SKIPPED` 态忽略输入） |

### 6.5 输入矩阵

| 输入 | 行为 |
| --- | --- |
| `SPACE`/`RETURN`/`ESC`/左键 | 跳过（§6.4） |
| `M` | 语音静音，**时刻表不变**，倒计时仍 `PAUSED` |
| `F1` | 沿用（调试开关） |
| 其它键 | 无响应（**不得**出 toast：会与字幕条抢注意力） |

| 字号 | `× scale` 后 `round`，**下限 12 px**；触下限即停止缩小 |
| 行距 / 槽位 | **不变**（UI 的 19 px 行距、152 px 区高是硬版式；槽位一变，§3.5 的切换目标与 `D` 的可读性假设全部脱钩） |
| 竖条宽 | `max(2, round(4 × scale))`。**下限 2**：1 px 在 `smoothscale` 后会被抹掉，而它是"当前步"的唯一指示物 |
| 重排 | **禁止**。空间不够 ⇒ 字号下限 + 第 7 槽合并行（UI §3.3.1） |

### 8.3 语音缺失（`assets/vo/` 为空 / `mixer` 失败 / `M`）

| 项 | 形态 |
| --- | --- |
| 时间轴 | **逐帧可复现**：走 fallback（段内 `D`、段间不变），与有语音时**目视一致**（只是没声） |
| 视觉 | 不显示"静音图标"、不加提示、不降字号 |
| 倒计时 | `PAUSED` 照常（暂停与有无声音无关） |
| 跳过 | 照常 |
| 日志 | 1 条 INFO（**不是 WARN**，AUDIO §3.8 明确「零 WARN 刷屏」） |

> **这是第一版就要实现的正常路径**（AUDIO §3.8 核心承诺）：TTS 授权未确认时上线只能发字幕版，`assets/vo/` 为空必须功能完整、零异常。

### 8.4 字段缺失 ⇒ 走 ARCH §4.4 的 L0–L3（唯一权威）

| 级别 | 播报 | 我这侧的时间轴 |
| --- | --- | --- |
| L0 完整 | ✅ | `n = min(len(yaku), 7)` |
| L1 无 `han_breakdown` | ✅（数字与 L0 同源） | 同 L0（`base` 由 `Σ yaku.han` 推） |
| L2 无 `yaku` | ✅ 但只有固定段 | `n = 0` ⇒ 段 1 只 1 行「明细不可用」不参与高亮；`ΣD = 0`，`TOTAL = 2820 + 96han` |
| L3 全缺 | ❌ 不播报 | 直接静态页 |

**判据**：`has_yaku_key = isinstance(win, dict) and "yaku" in win`。「有键但空」= 真 0 番（「无番（0 番）」），「无键」= 明细不可用（L2）。**两者文案必须不同**（ARCH §4.4）。

### 8.5 `--no-feel`

完全不播报：`feel.animations_on == False` ⇒ `bc` 不实例化、不注册跳过键、倒计时**不冻结**（必须完全等价 v2.0 行为）。字幕与六段信息仍**静态全量显示**。
