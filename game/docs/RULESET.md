### 1.2 牌面集合

| 项 | 冻结值 |
| --- | --- |
| 数牌花色 | `m`（万）、`p`（筒）、`s`（条），顺序 `m < p < s` |
| 数牌级 | `1..9` |
| 字牌 | `1z`=东、`2z`=南、`3z`=西、`4z`=北、`5z`=白、`6z`=发、`7z`=中（**共 7 种**） |
| 牌面种类 | **34**（`3 × 9 + 7`） |
| 每种副本数 | **4** |
| 总张数 | **136**（见 §1.1） |
| 编码 | 数牌 `^[1-9][mps]$`、字牌 `^[1-7]z$`（与 `PROTOCOL.md` §2.1 一致） |
| 排序键 | **先数牌后字牌**：`(suit_index, rank)`，`m=0, p=1, s=2, z=3`；数牌内 `rank` 1..9 升序、字牌内 `1z`..`7z` 升序；同牌面副本相邻（与 `PROTOCOL.md` §2.2 一致） |
| 花牌 | **无**（唯一仍在范围外的牌种类） |

**建议的内部牌 id（不在线上传输，供规则库实现使用）**：
`id = ((suit_index × 9) + (rank − 1)) × 4 + copy`（数牌，`suit_index ∈ {0,1,2}`）；字牌 `id = (27 + (z_index)) × 4 + copy`（`z_index = 0..6` 对应 `1z..7z`）。
合计 `34 × 4 = 136`，取值域 `0..135`。
反解（数牌）：`suit_index = id / 36`、`rank = (id % 36) / 4 + 1`、`copy = id % 4`；反解（字牌）：`face = id / 4 ∈ [27,33]`、`z_index = face − 27`、`copy = id % 4`。

### 1.3 牌山生成（确定性，必须逐字实现）

```cpp
std::vector<Tile> build_wall(uint64_t seed) {
  std::vector<Tile> wall;                     // 34 面 × 4 张 = 136，按 §1.2 顺序生成
  for (int sip = 0; sip < 3; ++sip)           // m, p, s
    for (int r = 1; r <= 9; ++r)
      for (int c = 0; c < 4; ++c) wall.push_back(make_tile(sip, r, c));
  std::mt19937 rng(static_cast<std::mt19937::result_type>(seed));
  for (int i = 107; i >= 1; --i) {            // Fisher–Yates（降序）
    std::uniform_int_distribution<int> dist(0, i);
    std::swap(wall[i], wall[dist(rng)]);
  }
  return wall;
}
```

| 约束 | 说明 |
| --- | --- |
| RNG | `std::mt19937`，以 `--seed` 初始化；**不得**替换为 `random_device` 或其他引擎 |
| 循环方向 | **必须** `i` 从 `n−1` 递减到 `1`；`j = uniform_int_distribution<int>(0, i)` |
| 牌山顺序 | `wall[0..]` 为**摸牌顺序**：先被摸走的在数组前部 |
| 复现契约 | 同一 `seed` ⇒ **完全相同的牌山序列**（t2 必须为此写单测） |

### 1.4 发牌（确定性）

1. `seat 0` 取 `wall[0..12]`（13 张）→ `seat 1` 取 `wall[13..25]` → `seat 2` 取 `wall[26..38]` → `seat 3` 取 `wall[39..51]`。
2. **庄家（`dealer`，变量，取值 0..3）**再取 `wall[52]` 作为第 14 张。
3. `remaining = 136 − 53 = **83**`；已摸牌计数 `draws_taken = 0`，第 `k` 次摸牌取 `wall[53 + k]`（`k` 从 0 起）。
4. 手牌下发前按 §1.2 排序规则排序（实现可用多重集 + 排序）。

> ⚠️ **v1.3 规格要求（不是建议）**：`DealTiles` 现硬编码「`hands[0]` 为庄家」（`mahjong_rules.cc:234`）。多局后庄家轮转，签名**必须**改为
> `DealTiles(const std::vector<Tile>& wall, int dealer)`，由 `dealer` 决定谁取第 14 张；`hands[]` 按座位下标存放（`hands[dealer].size() == 14`）。
> 牌山切分位置（第 1 条）不变，因此同一 `seed` + 同一 `dealer` 得到的四手牌与前缀切分完全一致；不同 `dealer` 只改变「第 53 张给谁」。

### 1.5 摸牌与杠补牌

| 事件 | 规则 |
| --- | --- |
| 普通摸牌 | `remaining > 0` ⇒ 取下一张，`remaining--`，玩家进入行动态 |
| 杠补牌（**明杠 / 暗杠 / 加杠三种都一样**，v1.3） | 杠声明成功并完成副露（或升级）后，**立即**从**同一牌山**取下一张，`remaining--`。不引入王牌/岭上牌 |
| `remaining` 的算法（**实现红线**） | 一律用**派生值** `remaining = kTileCount − next_index`（`room.cc:975` 现状），**不得**写 `remaining--` 的自减式；否则派生值与 `next_index` 漂移，客户端 `remaining` 显示错误 |
| 荒庄触发 | **需要摸牌（含杠补牌）而 `remaining == 0`** ⇒ 立即荒庄（§7） |
| 杠的可用性 | 鸣牌窗口只在 `remaining ≥ 1` 时提供 `kong`；打牌窗口只在 `remaining ≥ 1` 时提供 `ankan`/`kakan`（GAME_DESIGN §5.3） |

## 2. 座位、方位与手牌不变量

### 2.1 座位

| 项 | 冻结值 |
| --- | --- |
| 座位数 | 4（`seat 0..3`） |
| 出牌顺序 | `0 → 1 → 2 → 3 → 0`（逆时针） |
| 自家/下家/对家/上家 | 对座位 `s` 分别是 `s` / `(s+1)%4` / `(s+2)%4` / `(s+3)%4` |
| 庄家 | **变量 `dealer ∈ 0..3`**（首局 `0`，之后轮转或连庄，见 §7.3）；起手 **14** 张，**第一打不摸牌**；其余三家 13 张 |
| 连庄 / 庄家加成 / 场次分（v1.3） | 连庄：庄家和牌或荒庄时 `dealer` 不变、局号不增；庄家和牌 **+1 番**；连庄本身 **0** 加成（§6.1、§7.3） |
| 吃牌权限 | 仅放炮者的**下家** `(S+1)%4`（§4.2） |

### 2.2 手牌计数与不变量

记号：`concealed` = 未副露手牌张数；`melds` = 副露组数（每个杠计 **1** 组）；`kans` = **杠数（明杠 + 暗杠 + 加杠）**（v1.3 起不再只指明杠）。

| 状态 | 不变量 |
| --- | --- |
| 等待态（未轮到自己摸牌 / 已打牌完毕） | `concealed + 3 × melds = 13` |
| 行动态（摸牌后 / 副露后待打牌） | `concealed + 3 × melds = 14` |
| 物理持有 | `physical = concealed + 3 × melds + kans = (13 或 14) + kans` |
| 和牌逻辑张数 | **恒为 14**（每个杠按 3 张计入面子）；和牌物理张数 = `14 + kans` |

- 例：1 次明杠后等待态为 `concealed=10, melds=1, kans=1`（账面 `10+3=13`，实际持有 14 张）。
- 七对子要求 `melds == 0` 且 `kans == 0`（门前清）。

### 2.3 副露后的手牌变化表（实现直接照抄）

| 动作 | 触发条件 | `concealed` 变化 | `melds` 变化 | `kans` 变化 | 之后 |
| --- | --- | --- | --- | --- | --- |
| 碰 pong | 他家打出 `T`，`count(T,手牌) ≥ 2` | **−2** | +1 | 0 | 必须打牌 |

## 3. 和牌判定（t2 必须严格正确）

### 3.1 输入与总张数

```
can_win(concealed_multiset, melds[], winning_tile) -> bool
```

- `concealed_multiset`：本家**门前**手牌（不含副露牌），荣和时为 13 张手牌、自摸时为 14 张（含摸到的牌）。
- 判定使用 **`concealed + [winning_tile]` 的逻辑 14 张**（杠按 3 张计入面子，见 §2.2）。
- 荣和：`winning_tile` = 他家打出的那张；自摸：`winning_tile` = 刚摸到的牌（此时 `concealed` 已含它，实现上应避免重复加入 —— 见 §3.6 的实现约定）。
- `melds[]` 元素的 `tiles` 牌面必须与 `concealed` 的内容不冲突（同一张物理牌只能出现一次）。

### 3.2 标准型（4 组面子 + 1 对将）

面子 = 刻子（3 张同面）或顺子（同花色 rank 连续 3 张）；**明杠按刻子计**（账面 3 张）。

**字牌规则（v1.2 新增，冻结）**：

1. **字牌只能构成刻子 / 杠，不能构成顺子**（字牌不可吃）。顺子仅在同一数牌花色（`m`/`p`/`s`）内成立。
2. **和牌判定对字牌与数牌一视同仁**：仍按「每个牌面计数模 3、且恰好一对将」处理，**不需要**为字牌写特例分支；但**顺子检查必须排除字牌面**（`face ≥ 27` 或 `suit == z` 时不得进入顺子分支）。
3. 将牌可以是字牌（如 `5z 5z`），面子可以是字牌刻子（如 `1z 1z 1z`）。

参考算法（正确且足够快，实现方直接采用；`is_number(face)` 表示该面属于 `m`/`p`/`s`）：

```
is_standard(tiles, meld_count):
    need_groups = 4 - meld_count          # 已有副露的面子已固定
    if len(tiles) != need_groups*3 + 2: return false
    for p in distinct(tiles):
        if count(p) >= 2 and decompose(tiles - 2*p, need_groups): return true
    return false

decompose(rest, need):
    if need == 0: return empty(rest)
    t = min(rest)                          # 取最小牌面，避免重复枚举
    # A. 刻子（数牌与字牌通用）
    if count(t) >= 3 and decompose(rest - 3*t, need-1): return true
    # B. 顺子（t 必为顺子最小张；**仅限数牌**，且 rank 须 ≤ 7）
    if is_number(t) and rank(t) <= 7
       and has(rest, suit(t), rank(t)+1) and has(rest, suit(t), rank(t)+2):
        if decompose(rest - {t, t+1, t+2}, need-1): return true
    return false
```

- 正确性依据：以「最小牌面」为锚，它只能充当**将牌**（在 `is_standard` 外层枚举）、**刻子**或**顺子最小张**，不存在第四种归属，故不遗漏任何拆解；字牌因 `is_number` 为假而不进入顺子分支，其余行为不变。
- 复杂度：每次拆解最多 2 个分支、深度 ≤ 4，退化为常数级；**不做**性能优化/缓存（GAME_DESIGN t2 的 non-goal）。
- 副露面子（pong/chow/kong）已在 `meld_count` 中固定，不再参与拆解，因此「看他家已副露后吃碰条件变化」不影响本判定。
- ⚠️ **给规则库实现的坑**：若用「牌面下标连续」代替「同花色 rank 连续」做顺子判断，字牌面（如 `1z`=面 27、`2z`=面 28、`3z`=面 29）会被误判成顺子 —— 必须显式排除字牌。

### 3.3 七对子

```
is_seven_pairs(tiles):
    return len(tiles) == 14
        and number_of_distinct_faces(tiles) == 7
        and every face has exactly 2 copies
```

- 额外前置条件：`melds == 0` **且** `kans == 0`（门前清，§2.2）。
- **4 张同牌面不算作两对**（必须 7 个不同面各 2 张）。这是最易写错处，t2 单测必须覆盖（§10.3 N3）。

### 3.4 清一色

```
is_pure_one_suit(concealed, melds, winning_tile):
    suit = null
    for t in (concealed + [winning_tile] + all melds[].tiles):
        if not is_number(t): return false        # 字牌 ⇒ 不是清一色
        if suit == null: suit = suit_of(t)
        elif suit != suit_of(t): return false
    return suit != null
```

- 统计范围为**和牌的全部物理牌张**（门前手牌 + 副露牌面 + 和牌张），共 `14 + kans` 张。
- 清一色是**倍率标签**，不是独立牌型：它可以与标准型或七对子叠加（`M` 见 §6.1）。
- **字牌不计入清一色**：`pure_one_suit` 只指数牌单一花色（`m`/`p`/`s`）；含任何字牌即判定为假。本里程碑**无「字一色」**这一役（全字牌和牌 `tags` 为空，`M = 1`）。

- `tags` 取值域：`{}`、`{seven_pairs}`、`{pure_one_suit}`、`{seven_pairs, pure_one_suit}`（顺序固定 `seven_pairs` 在前）。
- **v1.3 说明**：`tags` 只是**向后兼容的子集**（协议 `win.tags` 与 `results[].win_type` 沿用此形状）；完整的番种判定与番数在 §6.4，出口是 `win.yaku[]`。**`tags` 不再与分数一一对应**（分数看 `han`/`multiplier`）。
- **本里程碑没有「必须满足某役才能和牌」的限制**：`tags` 为空也照常和牌（0 番和牌，得 1 分）。

### 3.6 实现约定与边界（避免误判）

1. 自摸调用时传入的 `concealed` **已包含**刚摸到的牌：此时判定应直接用 `concealed`（14 张）、`winning_tile` 仅用于 tag/展示，**不得重复加入**。建议 API 显式区分（§9）。
2. 荣和调用时 `concealed` 为 13 张（或 `13 − 3×melds`），判定时加入 `winning_tile`。
3. 张数不足/超出（如 13、15 张）一律判不和（除非该张数恰好满足对应分支的逻辑张数约束）。
4. 判定**纯函数**：不得修改传入的手牌、不得读全局状态、不得依赖随机。
5. 判定不看牌河、不看 `remaining`、不看 `seq`（本里程碑无振听、无宝牌、无海底/河底概念）。
6. **字牌**：只参与刻子/将（§3.2 第 1–3 条）；七对子同样允许字牌对子（例：`1z 1z 2z 2z 3m 3m 4m 4m 5p 5p 6p 6p 7s 7s` 是合法七对子）。**清一色不适用于字牌**（见 §3.4）。

## 4. 副露合法性

### 4.1 碰（pong）

- 前置：他家（打出者 `S`）打出 `T`；本家 `count(T, 手牌) ≥ 2`。
- 消耗：手牌移除 2 张 `T`；新增副露 `{"type":"pong","tiles":[T,T,T]}`（按 §1.2 排序）。
- 之后：鸣牌者成为 `current_seat`，开打牌窗口。

### 4.2 吃（chow）

- 前置：本家是打出者的**下家**（`本家 == (S+1)%4`）；手牌中存在 `{a,b}` 使 `{T,a,b}` 构成同花色顺子。
- **字牌不可吃（v1.2 冻结）**：`T` 为字牌（`1z`..`7z`）时**永远不产生 `chow` 选项**；`a`、`b` 也必须是数牌。字牌只能碰/杠（§4.1/§4.3）。
- 组合枚举（`T` 的 rank = `r`，且 `T` 为数牌）：候选 `{a,b} ∈ {{r−2,r−1}, {r−1,r+1}, {r+1,r+2}}`，rank 必须落在 `1..9`，且 `a`、`b` 都在手牌中。每个合法组合是一条独立的 `chow` 选项。
  例：`T = 3p` → `{1p,2p}`、`{2p,4p}`、`{4p,5p}`；`T = 5z` → **无 chow 选项**。
- 消耗：手牌移除 `a`、`b`；新增副露 `{"type":"chow","tiles":[a,b,T]}`（按 §1.2 排序）。
- `chow` 的 `tiles` 在协议中只携带手中的两张（`PROTOCOL.md` §4.6），被鸣牌 `T` 由 `from_seat` 的牌河确定。

### 4.3 明杠（kong）

- 前置：他家打出 `T`；本家 `count(T, 手牌) == 3`；**且 `remaining ≥ 1`**（否则不提供该选项）。
- 消耗：手牌移除 3 张 `T`；新增副露 `{"type":"kong","tiles":[T,T,T,T]}`（4 张，含额外张）；`kans++`。
- 之后：**立即补摸 1 张**（`remaining` 按 §1.5 的派生式重算），再开打牌窗口。
- 杠的第 4 张是「额外张」，账面按 3 张计入面子（§2.2）。
- **可见性**：`tiles` 4 张牌面对**四家全部公开**（与碰/吃同）。

### 4.4 暗杠（`ankan`，**v1.3 新增**）

| 项 | 规则 |
| --- | --- |
| 窗口 | **只在自家打牌窗口**（`window == "discard"`）；**不能**在鸣牌窗口、不能以他家打出的牌为对象 |
| 前置 | 本家为行动态（`concealed + 3×melds == 14`）；手中存在牌面 `F` 使 `count(F, concealed) == 4`；**且 `remaining ≥ 1`**（否则不提供该选项） |
| 消耗 | 手牌移除 4 张 `F`；新增副露 `{"type":"ankan","tiles":[F,F,F,F]}`（按 §1.2 排序）；`melds++`、`kans++` |
| 之后 | **立即补摸 1 张**（同 §4.3 的补牌口径）→ **重新开打牌窗口**（可继续暗杠/加杠/杠上开花和牌/打牌） |
| 张数 | 动作前 `c+3m=14` → 扣 4、`m+1` ⇒ 账面 13 → 补 1 ⇒ **14** ✅（§2.3） |
| 可见性 | 对**本家**暴露 4 张牌面；对**其他三家** `tiles` 为**空数组 `[]`**（只暴露「此处有一组暗杠」）；局终时最后一份 `state_sync` 揭示（GAME_DESIGN §4.4） |
| 门前清 | **不破门前清**（`menzen` 番成立，§6.1） |

### 4.5 加杠（`kakan`，**v1.3 新增**）

| 项 | 规则 |
| --- | --- |
| 窗口 | **只在自家打牌窗口**（同 §4.4） |
| 前置 | 本家为行动态；`melds` 中存在 `type == "pong"` 且牌面为 `F` 的组；手中 `count(F, concealed) ≥ 1`；**且 `remaining ≥ 1`** |
| 消耗 | 手牌移除 1 张 `F`；该 `pong` 组**就地升级**为 `{"type":"kakan","tiles":[F,F,F,F]}`（**组序不变**，第 4 张追加在末尾）；`melds` **不变**、`kans++` |
| 之后 | 同 §4.4（补摸 1 张 → 重新开打牌窗口） |
| 张数 | 动作前 14 → 扣 1、`m` 不变 ⇒ 账面 13 → 补 1 ⇒ **14** ✅（§2.3） |
| 门前清 | **必然破门前清**（加杠必然起于一个 `pong`，而 `pong` 已破门前清）—— 结构结论，无需判据 |
| **抢杠和** | **永久不做**（见 §4.6） |

### 4.6 永久不实现的副露（v1.3 裁决）

| 不实现 | 结论 | 原因 |
| --- | --- | --- |
| **抢杠和** | **永久不做**（不是「本期不做」） | ① 架构层：现有模型是「一次消息处理 = 一次原子状态转移 + 单向不可回滚」；抢杠和语义上要求**回滚**一次已完成的加杠转移，回滚面覆盖 `next_index` / `remaining` / `kans` / `melds` / `hands` / 牌河可见性 / 杠补牌记录 / 窗口 `seq` **八处**，任一处漏改即脏状态；② 玩家侧代价为**零**：加杠是自愿动作，不杠就不会被抢，也不会造成任何局面无法结束；③ 因此**加杠不引入新的应答窗口** —— 不占 15 s、不参与优先级裁决（§5.3）、不影响 AI 鸣牌门槛。**若将来要做，前置动作是先把状态机改成可补偿（快照 + 重放）** |
| 食替禁止 | 不实现 | 本规则允许副露后立即打出与副露组合相关的牌，无额外限制分支 |

## 5. 动作可选项计算与裁决

### 5.1 鸣牌窗口的 `options`

对打出牌 `T` 的座位 `S`，对每个 `s ≠ S`：

| 选项 | 出现条件 | 备注 |
| --- | --- | --- |
| `win` | `can_win(hand_s, melds_s, T)` 为真 | 有副露也可和；**无起和番**（0 番也可和） |
| `kong` | `count(T, hand_s) == 3` **且** `remaining ≥ 1` | 3 张时与 `pong` 并存；`remaining == 0` 时不提供 |
| `pong` | `count(T, hand_s) ≥ 2` | |
| `chow` | `s == (S+1)%4` 且 `T` 为**数牌**且存在合法 `{a,b}` | 1..3 种组合 ⇒ 1..3 条独立选项；**`T` 为字牌时恒无此选项**（§4.2） |
| `pass` | **永远存在** | 仅当存在非 `pass` 选项时才开窗 |

- `options` 内顺序固定：`win → kong → pong → chow → pass`（`PROTOCOL.md` §5.7）。
- 若所有 `s ≠ S` 都没有非 `pass` 选项 ⇒ **不开窗、不下发任何帧**，直接进入 `S+1` 的摸牌流程。

### 5.2 打牌窗口的 `options`

**合法动作及其冻结顺序**：`win → ankan → kakan → discard`

| 情况 | `options` |
| --- | --- |
| 本家（行动态 14 张逻辑牌）成和牌型（含自摸/天和） | `[{"action":"win","tiles":[]}]` |
| 手中某牌面恰好 4 张 **且** `remaining ≥ 1`（**v1.3**） | 追加 `{"action":"ankan","tiles":[F,F,F,F]}` |
| 存在 `pong` 组且手中有该面第 4 张 **且** `remaining ≥ 1`（**v1.3**） | 追加 `{"action":"kakan","tiles":[F]}`（只带**手中那一张**） |
| 其他 | `[]` |

- `options` 数组内顺序固定为 `win → ankan → kakan`（`discard` 排在最后，但**不进入 `options`**）。
- 打牌本身由 `discard` 帧表达，**不进入 `options`**；打牌窗口**不接受** `pass`（`PROTOCOL.md` §4.6）。
- 打牌窗口**永不**出现 `kong`（明杠只在鸣牌窗口，§5.1）；`ankan`/`kakan` 只在打牌窗口。两者不可混用。
- 出现 `ankan`/`kakan` 后仍**必须**在窗口内以 `discard` 收尾（除非杠后自摸和牌或继续杠）；超时/托管的默认动作仍是「打出刚摸到的那张牌」（§5.4 不变），**不会**自动杠。

### 5.3 优先级裁决（窗口结算）

1. **胡 > 杠 > 碰 > 吃 > 过**。
2. 同层级内：按距打出者 `S` 的逆时针顺序 `S+1`、`S+2`、`S+3` **最近者优先**（头跳）。
   - 例：`S+3` 与 `S+1` 都能荣和 ⇒ `S+1` 和牌。
   - 例：两个座位都能碰同一张（各持 2 副本）⇒ `S+1` 可碰则 `S+1`，否则 `S+2`。
3. 同一座位只执行其回复的**一个**动作。
4. 被裁决掉的意图**无任何副作用**（不扣手牌、不成副露、不获得牌权）。
5. 同一座位的 `options` 同时含 `kong` 与 `pong`（手中 3 张）时，由该座位自己选择；未选的那个不生效。

### 5.4 超时代打的默认动作（规则库提供的纯函数）

```
default_action(window, hand, melds, drawn_tile) -> Discard | Pass
  window == "discard":
      if drawn_tile exists:  discard(drawn_tile)          # 含杠补牌
      else:                  discard(sorted(hand).back()) # 庄家第一打 / 碰吃后待打牌
  window == "claim":
      pass
```

- 与 `PROTOCOL.md` §6.4、`GAME_DESIGN.md` §5.6.2 完全一致；断线托管用**同一函数**立即执行（不等 15 s）。
- 窗口时长与配置见 `PROTOCOL.md` §1.8（默认 15000 ms，区间 `[1000, 60000]`）。

## 6. 算分

### 6.1 番数、倍率与 `R`（**v1.3 番数制，整节重写**）

```
han_base   = Σ 成立番种的番数                  // 14 番种，见 §6.4（自摸不是番种）
han_dealer = han_base + (和牌者为庄家 ? 1 : 0)  // 唯一加成：庄家 +1
han        = min(han_dealer, 6)               // 硬封顶，庄家加成也受此封顶
R          = 2^han                            // R ∈ {1,2,4,8,16,32,64}
```

- 底分恒为 1（= `2^0`），不提供配置项。
- **无符数**（不引入第二套舍入源）。
- **连庄加成 = 0**（连庄的收益是多打一局）。
- **自摸不加番（v1.3 内修正）**：自摸的 ×2 已内建于 §6.2 支付公式的按家分摊（每家 `2R`、和牌者 `6R`）。若再把「自摸」计为番种，0 番自摸会变成每家 −4 / +12，与 v1.2 的 −2/+6 背离且构成双重计番。协议 `han_breakdown.tsumo` **保留但恒 0**。
- 旧口径（v1.2）的 `M ∈ {1,4,16}` **作废**；新旧行为对照与回归锚见 GAME_DESIGN §6.1（**唯一回归锚 = 0 番手牌新旧逐位相等**；七对子 ±4 → ±8、清一色 ±4 → ±64 等差额是 A 批设计意图，不是回归缺陷）。

### 6.2 支付（零和，整数）

| 情形 | 放炮者 | 和牌者 | 其余两家 | 说明 |
| --- | --- | --- | --- | --- |
| 荣和（ron） | `−R` | `+R` | `0` | 点炮者付 |
| 自摸（tsumo） | — | `+6R` | 各 `−2R` | 三家各付 `2R`，合计 `6R` |
| 荒庄（draw_exhausted） | — | `0` | `0` | 四家全 0 |

- 任何情形下 `Σ delta_score == 0`；全部为整数运算，**无舍入**。
- `win.per_payer = R`（荣和）/ `2R`（自摸）；`win.total = R`（荣和）/ `6R`（自摸）；`win.multiplier = R`。

记号：`门清` = 副露中不含 `pong`/`chow`/`kong`/`kakan`；**`ankan` 不破门清**。`all` = 门前手牌 + 全部副露牌面 + 和牌张。

| 序 | 番种（id） | 番数 | 判定条件 | 门清限定 | 吃和牌张 |
| --- | --- | --- | --- | --- | --- |
| 1 | 门前清 `menzen` | 1 | 副露无 pong/chow/kong/kakan（ankan 允许） | 定义即门清 | 否 |
| 2 | 断幺九 `tanyao` | 1 | `all` 无 rank∈{1,9} 数牌、无字牌 | 否 | 否 |

| 4 | 一杯口 `iipeikou` | 1 | 门清 且 存在两组同花色同起点顺子 | **是** | 否 |
| 5 | 箭刻 `yakuhai` | 1 × 组数（1..3） | 白发中每有一组刻子/杠 +1；**合并为一条**，`han` = 组数 | 否 | 否 |

| 12 | 小三元 `shousangen` | 2 | 白发中两组刻子/杠 + 第三组为将牌 | 否 | 否 |

> 结构推论：**七对子必然同时成立 `menzen`**（要求 `melds == 0` 且 `kans == 0`），因此七对子最少 3 番——不存在「2 番的七对子」。

**叠加与确定性（四条，冻结）**：
1. **全部累加求和**，不取最高。
2. 唯一排他组：一色组 `pure_one_suit`(5)/`honitsu`(2) 取高；实现**不需要互斥分支**（结构上不可能双命中）。其余互斥由牌型结构保证。
3. `han = max_{拆法 D} Σ番种(D)`，**禁止跨拆法拼凑**；**同番数取枚举序第一个**，枚举序冻结为：① 将牌牌面编号升序；② 面子按「本拆法最小未用牌面升序」；③ 同一最小牌面下**刻子先于顺子**（= `Decompose` 的回溯序）。
4. **0 番和牌合法**（无起和番），得 1 分（荣和）/ 每家 2 分（自摸）。

> ⚠️ **判番需要枚举全部拆法**：现有 `Decompose` 只返回 `bool`，v1.3 要求新增 `EnumerateDecompositions(concealed, melds)` 按上述冻结序产出全部「4 面子 + 1 将」拆法，并携带「和牌张落在哪一组」。**平和/一杯口/三色/一气/三暗刻 都必须在同一拆法内判定**。

## 7. 局终与场次（**v1.3：局终 ≠ 场终**）

### 7.1 一局结束条件（判据未变）

| 条件 | 判定 | 结果 |
| --- | --- | --- |
| 和牌 | 荣和（鸣牌窗口内 `win` 被裁决选中）或自摸（`action{win}`） | `reason = "win_ron"` / `"win_tsumo"`，按 §6.2 计分 |
| 荒庄 | **需要摸牌（含杠补牌）而 `remaining == 0`** | `reason = "draw_exhausted"`，四家 `delta_score = 0`，`win = null` |

- 一局**必然终止**：`remaining` 每次摸牌严格递减且下界为 0；和牌或荒庄二者必居其一。
- 单局上限：最多 **83** 次摸牌 + 1 次庄家第一打 = **84** 次打牌（§1.1 口径）；单座位牌河上限 `⌈84/4⌉ = **21**`。**三种杠只把一次普通摸牌换成一次补摸，不改变「摸牌:打牌 = 1:1」**，故 84/21 不因杠而变化。
- 不存在其他流局变体（无九种九牌/四风连打/四杠散了/三家和）；多响按 §5.3 头跳取唯一一家。

### 7.2 场次参数与计数（v1.3）

| 常量 / 字段 | 值 | 说明 |
| --- | --- | --- |
| `HANDS_PER_MATCH` | **4** | 一场 4 局（连庄不占局数） |
| `RENCHAN_MAX` | **4** | 单场**累计**连庄上限；达上限强制场终 |
| 单场局数上界 | **8** | `4 + 4` |
| `INTER_HAND_DELAY_MS` | **5000** | 局终 → 下一局 `game_start` 的间隔 |
| `dealer` | `0..3` | 当前庄家；首局 0 |
| `round_index` | **0 基 `0..3`**（与 `game_start.round_index` 同值；内部初稿称 `hand_no_`，作废） | 局号；**只在轮庄时 +1** |
| `round_count`（协议字段，`game_start` 下发） | **恒 4** | 本场固定局数（`HANDS_PER_MATCH`）；**不是**已打手数 |
| `hands_played`（内部计数，初稿称 `deal_count_`/`round_count_`，作废） | `0..8` | 已打手数（含连庄）；战绩/统计用此值；`game_end` 下发次数 = `hands_played`（场终时 = `match_end.hands_played(4) + renchan_count`） |
| `renchan_count` | `0..4` | 本场累计连庄次数 |
| `match_total[4]` | 整数 | 本场累计分；每局局终 `+= delta[s]` |

### 7.3 局终 → 连庄 / 轮庄 / 场终（**7 条转移判据，逐条冻结**）

```
S1 局开始     判据：进场 或 上一局 S5a；副作用：hands_played += 1；按 dealer 发牌
S2 摸打循环   判据：无
S3 局终       判据：win_ron / win_tsumo / draw_exhausted；副作用：match_total[s] += delta[s]（四家）
S4 连庄判定
   A 连庄   判据：reason 为和牌 且 winner == dealer
   B 连庄   判据：reason == draw_exhausted（荒庄无和牌者，一律按庄家荒庄）
   C 轮庄   判据：其他（闲家和牌）
   S4a 连庄：renchan_count += 1；dealer 不变；round_index 不变
   S4b 轮庄：dealer = (dealer+1)%4；round_index += 1
S5 场终判定
   D 场终   判据：round_index ≥ HANDS_PER_MATCH(4)（0 基，4 即越界）
   E 场终   判据：renchan_count > RENCHAN_MAX(4)     ← 兜底，保证一场必然终止
   F 下一局 判据：否则
   S5a：等 INTER_HAND_DELAY_MS → 回到 S1
   S5b：按 match_total 降序排名（同分并列同名次、后续跳号、无 tiebreak）→ match_end → 回收房间
```

- **一场必然终止**：`round_index` 与 `renchan_count` 均单调不减且有硬上界 ⇒ 最多 8 局。
- **局终不销毁房间**：房间生命周期 = 一场。局间状态拒绝一切对局帧（`BAD_REQUEST`）。
- 场终 `Σ match_total == 0`（每局零和的归纳）。

## 8. 确定性、可复现与纯函数约束

1. 牌山生成只依赖 `--seed`（§1.3）；同一 seed 必须得到完全相同的牌山与发牌结果。
2. 规则库**不得**读墙钟、不得用 `std::random_device`、不得依赖全局可变状态；同一输入必须给出同一输出。
3. AI 与托管策略（`GAME_DESIGN.md` §7）同样是确定性的，但**不属于规则库**；规则库只提供 `default_action`（§5.4）与判定/计分函数。
4. 算分与判定必须可重入、可并发调用（无共享缓存），以便 RoomActor 在多座位场景下安全使用。

## 附录 C：常见实现坑（t2 重点自查）

1. **七对子不能含 4 张同面**（N3）；也不能在有副露时成立（N8）。
2. **杠在账面上按 3 张计**：和牌逻辑张数恒为 14，物理张数 `14 + kans`；不要用 `hand.size() == 14` 硬判（有杠时物理张数不同）。
3. **自摸调用不要重复加入和牌张**（§3.6 第 1 条）。
4. **清一色统计必须包含副露与和牌张**，不能只统计门前手牌。
5. **`remaining == 0` 时必须先判荒庄再摸牌**，不得越界访问牌山。
6. **同一 seed 必须同牌山**：RNG 引擎、分布与循环方向都不能换（§1.3）。
7. **总张数口径**：总张数冻结为 **136**（3 门 × 9 级 + 7 种字牌 = 34 牌面 × 4，§1.1/§1.2）。**不要**再按 108 建牌山；字牌编码 `1z`..`7z`，排序**数牌在前、字牌在后**。
8. **字牌不可吃**：顺子只能在同一数牌花色内成立（`m`/`p`/`s`）；字牌只能作刻子/杠。和牌判定对字牌一视同仁（按牌面计数模 3 + 恰好一对将），**不要**为字牌写特例分支，但**必须**在顺子检查里排除字牌面（否则 `id/4 ≥ 27` 的面会被误当成顺子）。
9. **清一色判定**：`pure_one_suit` 只指数牌单一花色（`m`/`p`/`s`）；**全字牌不可判为清一色**（v1.3 仍无「字一色」番种）。v1.3 起清一色是 **5 番番种**，另有 `honitsu`（一门数牌 + 字牌）2 番承接「有字牌的一色手」。
10. **判番必须枚举拆法**：`Decompose` 只返回 `bool`，判番需要 `EnumerateDecompositions`（§6.4）。同一手牌可能有多种拆法，必须按冻结枚举序取「番数最大者；同番取第一个」，**不得跨拆法拼凑番种**。
11. **暗杠/加杠的台账不要另开公式**：三种杠都满足 `concealed + 3×melds ∈ {13,14}` 与 `physical = 上式 + kans`（§2.2、§2.3 表）。
12. **杠补牌不要写 `remaining--`**：`remaining` 是派生值 `kTileCount − next_index`（§1.5）。写自减式会与 `next_index` 漂移。
13. **发牌必须带 `dealer`**：`DealTiles(wall, dealer)`（§1.4），否则第二局起庄家位置错，`hands[0]` 恒被当成庄家。
14. **场终必须可达**：`round_index` 与 `renchan_count` 都有硬上界（4/4），实现不得让连庄无界（§7.3）。
